Reference 0002

Safe Write and Outbox Checklist

A compact checklist for turning retry-prone API commands into durable facts and reliably published events.

The Recurring Shape

CommandClient sends intent plus an idempotency key.
TransactionValidate, mutate source state, record the key, and insert outbox event.
CommitThe command becomes a durable business fact.
RelayPublisher drains outbox rows and sends them to the log.
ConsumersDownstream systems dedupe, process, and materialize state.

Schema Atoms

Atom Purpose Common constraint
idempotency_keys Remember a caller's request identity and semantic response. UNIQUE(caller_id, key)
subscriptions Store source-of-truth business state. Version, state transition, or row lock guards.
outbox_events Store messages in the same transaction as the state change. UNIQUE(aggregate_type, aggregate_id, sequence)
processed_events Let consumers ignore duplicate event deliveries. UNIQUE(consumer_name, event_id)

Failure Checklist

  • If the client times out, retry with the same idempotency key.
  • If the service sees the same key and same intent, return a semantically equivalent response.
  • If the service sees the same key and different intent, reject it as a conflict.
  • If the database commits, the outbox row must already exist.
  • If the database rolls back, no outbox row should be publishable.
  • If the relay crashes after publishing, expect duplicate delivery after restart.
  • If duplicates are possible, consumers need event IDs and idempotent writes.
  • If ordering matters, partition and sequence by the aggregate that needs order.

Useful Questions

  1. What exact operation is safe to retry?
  2. Who creates the idempotency key: caller, SDK, gateway, or service?
  3. Where is the key recorded atomically with the mutation?
  4. What response should a retry receive after the first request committed?
  5. Can the relay publish twice, and how do consumers dedupe?
  6. What aggregate key determines required ordering?
  7. How do you rebuild or replay if the relay was broken?
