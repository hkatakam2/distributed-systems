Reliability Controls Checklist

A compact guide for choosing timeouts, retries, backoff, circuit breakers, bulkheads, load shedding, and graceful degradation across backend service boundaries.

The Recurring Shape

BudgetEvery request has a finite time budget.
RetryRetry only safe transient failures with limits.
SpreadBackoff and jitter prevent synchronized pressure.
IsolateBulkheads keep one failure from consuming all capacity.
DegradeServe a smaller honest result before full collapse.

Control Selection

Problem Control Common trap
A dependency is slow or never responds. Deadline or timeout with cancellation. Letting callers wait until queues and threads are exhausted.
A transient failure may succeed soon. Retry with bounded attempts. Retrying unsafe writes without idempotency or retrying forever.
Many clients retry at the same time. Exponential backoff plus jitter. Creating a synchronized retry storm after an outage.
A dependency is repeatedly failing. Circuit breaker with half-open probes. Continuing to spend capacity on calls expected to fail.
One path can consume shared resources. Bulkhead pools, queue limits, or concurrency limits. Using one global pool for critical and optional work.
Load exceeds service capacity. Backpressure, load shedding, quotas, or admission control. Accepting work that cannot finish before its deadline.
The full response cannot be built reliably. Graceful degradation with an explicit contract. Failing the whole request because an optional feature failed.

Vocabulary

Deadline: an absolute time by which the caller no longer wants the result.

Timeout: a maximum wait for one operation or phase, such as connect, request, or read.

Retry budget: a limit on how many retry attempts a caller may spend so retries do not dominate traffic.

Backoff: increasing delay between retry attempts after repeated failures.

Jitter: randomness added to retry delays so clients do not retry in synchronized waves.

Circuit breaker: a stateful guard that fails fast when a dependency appears unhealthy, then probes for recovery.

Bulkhead: isolated capacity for a dependency, tenant, priority, or feature so one overload stays contained.

Backpressure: a signal or limit that slows producers when consumers cannot keep up.

Load shedding: intentionally rejecting lower-priority work when accepting it would hurt more important work.

Graceful degradation: returning a smaller, older, or less personalized result while preserving the core user contract.

Design Checklist

  1. What user-visible deadline does this request need to meet?
  2. How much of that budget can this dependency spend?
  3. Is the operation safe to retry? What makes duplicate attempts harmless?
  4. How many retries are allowed, and where is the retry budget enforced?
  5. Is backoff jittered so clients spread out after failure?
  6. What happens when the dependency is clearly unhealthy?
  7. Which resources are isolated for critical, optional, tenant, or dependency-specific work?
  8. Which work is shed first under overload?
  9. What degraded response is honest and useful?
  10. Which metrics prove the control is helping instead of hiding a worse failure?

Metric Checklist

  • Deadline exceeded count and timeout rate by dependency.
  • Retry attempts per original request and retry success rate.
  • Retry budget exhausted count.
  • Circuit breaker state changes, open duration, and probe results.
  • Pool saturation, queue depth, queue age, and rejected work.
  • Degraded response rate by feature and priority class.
  • User-visible latency, errors, freshness, and correctness after degradation.
